# Economy, inventory and crafting architecture

## Confirmed product decisions

- Inventory, crafting and merchant use compact in-world panels inspired by Albion Online and Minecraft; they must not cover the full viewport.
- Support every weapon branch currently present in `albion-weapon-branches.json`, while keeping item families data-driven so future weapons and armor can be added without UI rewrites.
- Weapon blueprints are consumed by each crafting operation.
- Crafting is available at dedicated stations.
- There is exactly one physical merchant on neutral territory, outside both teams' safe zones.
- Item tier is material-driven and has five levels (T1-T5). Tier is distinct from craft quality.
- Craft quality has four outcomes: ordinary, good, excellent, outstanding.
- Consumables have rarity grades and are generated by low-probability loot rolls, independently from material tier.
- Every equipment instance stores current and maximum durability.
- On death, equipped gear is rolled independently: it either breaks and is destroyed, or drops into the world for another player to loot. Higher tier means higher break probability. Backpack contents are not automatically dropped.
- Server owns inventory, item instances, equipment, durability, blueprints, crafting, trade, loot and death-drop resolution.
- Player inventory/profile data survives reconnects and server restarts, but a round reset deliberately wipes every profile, including offline players, and clears inventory, equipment, factories, blueprints, craft jobs and world gear drops. A starter T1 broadsword is restored so the next round can begin. This reset is global and is not limited to currently connected players.

## Identity and persistence

The current prototype has no account/login system and creates a new random player ID for every WebSocket connection. A display name is not a safe account key. The first implementation uses a random client profile token stored in browser local storage and validated server-side. This is a reconnect identity, not account-grade authentication; users can transfer it and losing browser storage loses access to the profile. A future account system should replace this token.

The server writes profile data atomically to `GAME_DATA_DIR/player-profiles.json`. Player-owned crafting stations and active crafting jobs are included in the saved profile and restored on reconnect. Render must mount a persistent disk and set `GAME_DATA_DIR` to its mount path. Without a mounted persistent disk, the server filesystem may be ephemeral and restart persistence cannot be guaranteed.

## Tier and quality

T1-T5 are material tiers. Tier drives base item power, durability and death-break chance. Craft quality is a separate random roll and adds a smaller power modifier. Quality must never silently change the material tier.

## Death and durability

Only equipped gear is subject to the death drop/break roll. Each equipped item has its own durability and tier. A surviving item becomes a world loot drop with an owner-independent pickup state. A broken item is deleted. Durability is consumed by relevant use events and must be clamped at zero. Exact durability-loss values and the death-break percentages are balance configuration, not client input.

## Loot

Consumable drop definitions are data-driven and have lower chances than ordinary resource/material yields. Initial implementation should roll consumables on successful resource gathering; later the same table can be reused by PvE and event loot.

## Neutral merchant and compact UI

There is one visible merchant NPC at the central neutral position (world x=20.7, z=0), outside the team safe zones. Players use F to interact; E remains reserved for the weapon ability. Inventory, equipment, crafting and merchant panels are compact overlays, not full-screen screens, and leave the 3D world visible.

The merchant sells base/refined materials, consumables and one-use weapon blueprints, and buys stackable goods plus spare weapons/armor from the backpack. Gear resale is server-priced from tier, quality and remaining durability: `floor(20 × tierOrder² × qualityFactor × durabilityRatio × 0.55)`, with a minimum of 1 gold. Equipped items cannot be sold directly; unequip them first.

## Implementation status and validation

Implemented on `feature/economy-inventory-crafting` (PR #8, draft):

- Data-driven T1-T5 tiers, four craft-quality grades, recipes for all weapon IDs in the current server catalog, and weighted consumable drop definitions.
- Atomic JSON profile store, reconnect hydration, persistent player-built stations and craft jobs, plus a global round-reset wipe (including offline profiles).
- One neutral merchant, server-side distance checks for trade/blueprint purchase/gear resale, forge-only weapon crafting, gear equip, durability loss, death break/drop and pickup.
- Compact inventory, equipment, crafting, factories and merchant tabs; local weapon presentation is hidden when the server reports no equipped weapon.

Latest GitHub Actions validation passed on the PR branch: economy/profile unit tests, loot/durability/death-drop tests, crafting/equipment engine tests, a two-client server-handler integration test (merchant range enforcement, reconnect hydration and round reset), existing lobby/siege integration tests, and JavaScript syntax checks. The server integration test uses a mocked WebSocket transport around the real server handler; it does not prove browser rendering or live network behavior.

Not yet verified: browser automation/visual playthrough, a positive end-to-end path through the siege gate to buy a blueprint and craft at a built forge, and two-client testing against the deployed Render service. Render persistent-disk configuration is also external to this repository and remains a deployment prerequisite.

The first implementation has weapon instances and armor-compatible data paths, but the current playable catalog contains weapons only; armor item definitions and armor slots remain future content.
